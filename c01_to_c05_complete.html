C01

Apache Spark vs Hadoop

Analyze the similarities and differences between Spark and Hadoop

What is Hadoop?
DApache Hadoop
Hadoop is an open-source framework for storing and processing large datasets in a distributed manner across clusters of computers using simple programming models. It has two core parts:

HDFS (Hadoop Distributed File System) — stores data across multiple machines in blocks (default 128MB each).
MapReduce — the processing engine that reads from disk → processes → writes back to disk at every single step.

This disk-based processing makes Hadoop slow for iterative tasks like machine learning algorithms that need to go over the same data many times.
ConceptHadoop MapReduce flow for a 3-step job
// HADOOP — reads/writes DISK at every step
Step 1: HDFS → Map → DISK WRITE → Shuffle → DISK WRITE → Reduce → HDFS
Step 2: HDFS → Map → DISK WRITE → Shuffle → DISK WRITE → Reduce → HDFS
Step 3: HDFS → Map → DISK WRITE → Shuffle → DISK WRITE → Reduce → HDFS

Result: 3 steps = 6 disk operations. Disk is 1000x slower than RAM!

// ML with 100 iterations on Hadoop:
100 iterations × 6 disk ops = 600 disk operations. Extremely slow.
What is Apache Spark?
DApache Spark
Apache Spark is an open-source, in-memory distributed computing framework that processes data in RAM instead of reading/writing to disk between steps. It is built on the concept of RDDs (Resilient Distributed Datasets) and is 100x faster than Hadoop MapReduce for in-memory operations and 10x faster on disk.

Spark does NOT replace HDFS — it replaces only the MapReduce computation engine. Spark uses HDFS for storage but processes data in memory.
ConceptSpark in-memory flow
// SPARK — reads disk ONCE, all processing in RAM
Load: HDFS → RDD in RAM (one-time disk read)

Step 1: RAM → transform → RAM
Step 2: RAM → transform → RAM
Step 3: RAM → transform → RAM

Save: RAM → HDFS (one-time disk write)

Result: 3 steps = 2 disk ops. Everything else in memory!
ML with 100 iterations = only 2 disk ops (1 read + 1 save).

Scala Language for Apache Spark

DScala Language
Scala (Scalable Language) is a general-purpose, statically typed, object-oriented and functional programming language that runs on the JVM. Created by Martin Odersky in 2003. Apache Spark is written in Scala, making it the native language of Spark. Scala's concise syntax lets you write in 5 lines what Java needs 60 lines for.
val vs var
Dval — immutable
val declares an immutable variable. Once assigned, value cannot change. Like final in Java. In Spark, RDDs are always val because RDDs are immutable by design.
Dvar — mutable
var declares a mutable variable. Value can be changed anytime. Like a normal variable in Java. Used when value needs to be updated (e.g., accumulators).

In-Memory Computation of RDDs

Discuss in-memory computation of RDDs for faster processing — from cluster 3.txt

DRDD — Resilient Distributed Dataset
R = Resilient — Fault tolerant. If a node fails, Spark recomputes lost partitions using the Lineage Graph (history of transformations). No data replication needed.
D = Distributed — Data is split into partitions and spread across multiple Worker nodes in the cluster for parallel processing.
D = Dataset — A collection of data elements of any type (integers, strings, tuples, objects).

RDDs are immutable — operations create new RDDs. Lazy evaluated — transformations don't execute until an Action is called. In-memory — data stays in RAM for fast repeated access.
DDAG — Directed Acyclic Graph (Lineage)
The DAG is Spark's execution plan — the chain of transformations that created an RDD. Directed = has direction (steps flow one way). Acyclic = no loops. When a node fails and a partition is lost, Spark re-runs the DAG from the source to rebuild it — this is how fault tolerance works without data copies.

Transformations — LAZY (build the DAG)
DTransformation
A Transformation is an operation on an RDD that returns a new RDD. Transformations are LAZY — they do not execute. Spark builds a DAG (execution plan) and waits for an Action to actually run everything. Examples: map(), filter(), flatMap(), reduceByKey().

Actions — TRIGGER Execution
DAction
An Action is an operation that triggers execution of all pending transformations and returns a result to the driver program (or writes to storage). Actions are EAGER — they run immediately. Without an Action, nothing executes. Examples: collect(), count(), take(), save().

Word Count — Complete Program
ScalaStandard RDD word count — write this on paper!
// Step 1: Load file into RDD (each element = 1 line)
var a = sc.textFile("C:/Users/file.txt")

// Step 2: flatMap — split lines into words (flat list)
val words = a.flatMap(_.split(" "))

// Step 3: map — give each word a count of 1
val pairs = words.map(word => (word, 1))

// Step 4: reduceByKey — add counts for same word
val counts = pairs.reduceByKey(_ + _)

// Step 5: Action — triggers execution!
counts.collect().foreach(println)
(Hello,2)   (World,1)   (Spark,3) ...
Transformation vs Action — Golden Rule:
Transformations (map, filter, flatMap, reduceByKey) = LAZY. Return new RDD. Build the DAG. Don't execute.
Actions (collect, count, take, save, foreach) = EAGER. Trigger execution. Return result to driver.

Spark MLlib — Machine Learning

Apply Spark MLlib for performing machine learning in big data environment

DMLlib — Machine Learning Library
MLlib is Apache Spark's built-in, distributed machine learning library. It provides scalable implementations of common ML algorithms that run across a cluster in parallel — making it much faster than single-machine ML.

MLlib works on DataFrames (the ml package) and operates through a Pipeline: data → features → model training → predictions.

Key components: Estimator (fits a model on data, e.g. LinearRegression), Transformer (transforms data, e.g. VectorAssembler), Pipeline (chains multiple stages together).

MLlib Algorithms

ClassificationLogistic Regression, Decision Tree, Naive Bayes — predict which category (spam/not spam, pass/fail)
RegressionLinear Regression — predict a number (house price, temperature)
ClusteringK-Means — group similar data without labels (customer segments)
RecommendationALS — collaborative filtering (like Netflix recommendations)
DVectorAssembler
VectorAssembler is a Transformer that combines multiple DataFrame columns into a single features vector column. All Spark ML algorithms require one single column called "features" of type Vector. VectorAssembler creates that column from your data columns.
Linear Regression
PySparkStandard Linear Regression — write this on paper
from pyspark.sql import SparkSession
from pyspark.ml.regression import LinearRegression
from pyspark.ml.feature import VectorAssembler

spark = SparkSession.builder.appName("LR").getOrCreate()

# Step 1: Create data
data = [(1.0, 2.0, 5.0),
        (2.0, 3.0, 7.0),
        (3.0, 4.0, 9.0)]
df = spark.createDataFrame(data, ["x1", "x2", "label"])

# Step 2: Assemble features into one vector column
assembler = VectorAssembler(
    inputCols=["x1", "x2"],
    outputCol="features"
)
df = assembler.transform(df)

# Step 3: Train model
lr = LinearRegression(featuresCol="features", labelCol="label")
model = lr.fit(df)        # fit() = train the model

# Step 4: Predict
predictions = model.transform(df)   # transform() = apply model
predictions.show()
K-Means Clustering — Most Asked!
DK-Means Clustering
K-Means is an unsupervised clustering algorithm. It groups data into k clusters where each data point belongs to the cluster with the nearest centroid (cluster center). k is the number of clusters you specify. K-Means iterates until cluster centers stop changing (converges). Spark's MLlib K-Means is distributed — runs across the cluster in parallel.
PySparkK-Means — write this on paper!
from pyspark.ml.clustering import KMeans
from pyspark.ml.feature import VectorAssembler
from pyspark.sql import SparkSession

spark = SparkSession.builder.appName("KMeans").getOrCreate()

# Sample data — 4 points, clearly 2 groups
data = [(0.0, 0.0), (1.0, 1.0),
        (9.0, 8.0), (8.0, 9.0)]
df = spark.createDataFrame(data, ["x", "y"])

# Assemble x, y into single features column
assembler = VectorAssembler(
    inputCols=["x", "y"],
    outputCol="features"
)
df = assembler.transform(df)

# Train K-Means with k=2 clusters
kmeans = KMeans(k=2, seed=1)
model = kmeans.fit(df)

# Print cluster centers
centers = model.clusterCenters()
print("Cluster Centers:", centers)
Cluster Centers: [array([0.5, 0.5]), array([8.5, 8.5])]

# Assign cluster to each point
result = model.transform(df)
result.show()

Big Data Processing with DataFrames

Workflows, processing and analysis of big data using Apache Spark — from cluster 4.txt & method 1 file

DDataFrame
DataFrame is a distributed collection of data organized into named columns — like a table in a relational database or a spreadsheet. Built on top of RDD, it adds schema (column names + types), SQL support, and automatic optimization via the Catalyst Optimizer.

DataFrame advantages over RDD: named columns, automatic optimization, SQL queries, better error messages, easier API.
DSparkSession
SparkSession is the unified entry point for Spark 2.x+. It combines SparkContext + SQLContext + HiveContext into one object. Auto-created as spark in spark-shell. Used for DataFrames, SQL, and streaming. SparkSession internally contains SparkContext (spark.sparkContext).

DSpark SQL
Spark SQL is Spark's module for structured data processing that allows running standard SQL queries on DataFrames. You first register a DataFrame as a temporary view (like a virtual table), then run any SQL query on it using spark.sql(). This returns a new DataFrame as output.
